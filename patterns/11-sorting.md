# Сортировки

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

На собеседовании сортировка встречается в двух ролях. Чаще — как **первый шаг**, который за O(n log n) открывает дорогу двум указателям, бинарному поиску или жадному алгоритму. Реже — как самостоятельная тема: написать quicksort, сравнить алгоритмы, объяснить устойчивость.

---

## 1. Когда сортировать первым шагом

Вопрос: **изменится ли ответ, если переставить элементы входа?** Если нет — сортировка разрешена и, скорее всего, полезна.

| Что написано в условии | Что даёт сортировка |
|---|---|
| Найти пару, тройку, ближайшие по значению | два указателя, соседи рядом |
| Отрезки, встречи | слияние и жадный выбор |
| Анаграммы, группировка | одинаковые элементы встают рядом, отсортированная строка служит ключом |
| «k-й по величине», медиана | элемент оказывается на своём месте |
| Собрать наибольшее число, упорядочить по правилу | свой компаратор |

**Когда сортировать нельзя:**

- Нужны исходные индексы. Выход — сортировать пары «значение, индекс» или массив индексов.
- Ответ — подмассив или подпоследовательность, то есть порядок элементов важен.
- Требуется O(n), а сортировка даёт O(n log n).

## 2. Алгоритмы

| Алгоритм | Время | Память | Устойчивая | Когда выбирают |
|---|---|---|---|---|
| Слиянием | O(n log n) всегда | O(n) | да | связные списки, нужна устойчивость, подсчёт инверсий |
| Быстрая | O(n log n) в среднем, O(n²) в худшем | O(log n) на рекурсию | нет | массивы, на практике самая быстрая |
| Пирамидальная | O(n log n) всегда | O(1) | нет | нужна гарантия времени без дополнительной памяти |
| Подсчётом | O(n + k) | O(k) | да | значения из маленького диапазона размера k |

**Устойчивость** — равные элементы сохраняют исходный относительный порядок. Важна при сортировке по нескольким ключам по очереди.

В Java `Arrays.sort` для примитивов — быстрая сортировка с двумя опорными элементами, неустойчивая. Для объектов и в `Collections.sort` — TimSort, устойчивая. Компаратор к `int[]` применить нельзя: нужен `Integer[]` или сортировка индексов.

### Быстрая сортировка

Идея: выбрать опорный элемент, переставить массив так, чтобы меньшие оказались слева, а большие справа, и рекурсивно отсортировать обе части.

Разбиение Ломуто — это шаблон «чтение и запись» из заметки про два указателя:

```java
int partition(int[] a, int lo, int hi) {     // сортируем [lo, hi] включительно
    int pivot = a[hi];
    int i = lo;                              // [lo, i) — элементы меньше опорного
    for (int j = lo; j < hi; j++) {
        if (a[j] < pivot) {
            swap(a, i, j);
            i++;
        }
    }
    swap(a, i, hi);                          // опорный встаёт на своё место
    return i;
}
```

Смысл указателей: `[lo, i)` — меньше опорного, `[i, j)` — не меньше, `[j, hi)` — ещё не просмотрено.

**Когда получается O(n²).** Опорный элемент каждый раз оказывается минимумом или максимумом: уже отсортированный массив при выборе последнего элемента, либо массив из одинаковых элементов. Лечится случайным выбором опорного и разбиением на три части.

Примеры из репозитория:

- [EffectiveQuicksort](../src/ya/algorithm_course/third_sprint_sort/final_test/EffectiveQuicksort.java) — на месте, со случайным опорным элементом и компаратором.
- [QuickSortAlgorithms](../src/stepik/algorithms/QuickSortAlgorithms.java) — разбиение на три части (меньше, равно, больше): на массиве из одинаковых элементов работает за O(n).
- [sortColors](../src/leetcode/medium/MediumSolutions.java) (LC 75) — то же разбиение на три части как отдельная задача. [ColorCountingSort](../src/ya/algorithm_course/third_sprint_sort/ColorCountingSort.java) — та же задача подсчётом, в два прохода.

**Quickselect.** Чтобы найти k-й элемент, сортировать всё не нужно: после разбиения идём только в ту часть, где лежит позиция k. В среднем O(n).

### Сортировка слиянием

[MakeMergeSort](../src/ya/algorithm_course/third_sprint_sort/MakeMergeSort.java). Делим пополам, сортируем половины, сливаем двумя указателями. Слияние — тот же шаблон, что в Merge Sorted Array.

Удобно фиксировать полуинтервал `[left, right)`: тогда середина `mid = (left + right) / 2`, половины — `[left, mid)` и `[mid, right)`, длина — `right - left`, и нигде нет `+ 1` и `- 1`. База рекурсии — длина меньше 2.

### Пирамидальная сортировка

[HeapSort](../src/ya/algorithm_course/fifth_sprint_trees/final_task/HeapSort.java). Складываем элементы в кучу и по одному извлекаем из неё вершину (в решении куча максимальная, с компаратором).

## 3. Свой компаратор

[BigNumber](../src/ya/algorithm_course/third_sprint_sort/BigNumber.java) (≈LC 179). Нужно склеить числа в наибольшее число. Сравнивать числа напрямую нельзя: 9 должно идти раньше 34. Правило: `a` раньше `b`, если строка `a + b` больше строки `b + a`.

```java
Arrays.sort(strs, (a, b) -> (b + a).compareTo(a + b));
```

Особый случай: если все числа нули, ответ `"0"`, а не `"000"`.

Требования к компаратору:

- Не вычитать: `a - b` переполняется. Использовать `Integer.compare(a, b)`.
- Быть согласованным: если `a < b` и `b < c`, то `a < c`. Иначе Java может бросить исключение «Comparison method violates its general contract».
- Несколько ключей: `Comparator.comparingInt(...).thenComparing(...)`.

## 4. Типичные ошибки

- Отсортировали и потеряли исходные индексы, которые нужны в ответе.
- Смешаны соглашения о границах: в одном месте `[lo, hi]`, в другом `[lo, hi)`.
- Рекурсия без уменьшения отрезка: в быстрой сортировке опорный элемент надо исключать из обеих частей.
- Фиксированный опорный элемент — O(n²) на отсортированном входе.
- Компаратор через вычитание.

## 5. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| Сортировка для k-го элемента | куча размера k или quickselect | не нужен порядок всех элементов |
| Сортировка для поиска пары | хеш-мапа | нужно O(n) или исходные индексы |
| Сортировка сравнениями | подсчёт | значений мало: цвета, буквы, возраст |
| Сортировка частот | корзины по частоте (LC 347) | частота не превышает n — O(n) вместо O(n log n) |
