# Хеширование и префиксные суммы

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

Главная мысль: хеш-мапа меняет память на время. Она отвечает за O(1) на вопрос «я это уже видел?», и поэтому превращает перебор пар O(n²) в один проход O(n). Перед кодом надо решить одно: **что будет ключом и что значением**.

---

## 1. Как узнать задачу

| Что написано в условии | Подход |
|---|---|
| «Есть ли дубликат», «встречалось ли уже» | `HashSet` |
| «Сколько раз встречается», «самый частый», анаграммы | мапа частот или массив `int[26]` |
| Найти пару с нужной суммой в **неотсортированном** массиве | мапа «значение → индекс» |
| «Сгруппировать по признаку» | мапа «признак → список» |
| Взаимно-однозначное соответствие символов или слов | две мапы, в обе стороны |
| Подмассив с суммой ровно k, есть отрицательные числа | префиксные суммы + мапа |
| Много запросов «сумма на отрезке» | массив префиксных сумм |
| «Произведение или сумма всех, кроме текущего», без деления | префикс слева и суффикс справа |
| Вставка, удаление и поиск за O(1) | мапа в связке с другой структурой |

## 2. Хеш-мапа: что ключ и что значение

Три типовых варианта:

- **Значение → индекс.** [twoSum](../src/leetcode/easy/EasySolutions.java) (LC 1): для каждого `x` ищем в мапе `target - x`.
- **Значение → количество.** [majorityElement](../src/leetcode/easy/EasySolutions.java) (LC 169), [PatternSearch](../src/leetcode/challenges/PatternSearch.java) (LC 187, частоты подстрок длины 10).
- **Признак группы → элементы.** Group Anagrams (LC 49): ключ — отсортированные буквы слова.

**Порядок «проверить, потом положить».** В Two Sum сначала ищем пару для текущего элемента и только потом кладём его в мапу. Иначе элемент найдёт сам себя (при `target = 2 * x`).

```java
Map<Integer, Integer> indexByValue = new HashMap<>();
for (int i = 0; i < nums.length; i++) {
    Integer j = indexByValue.get(target - nums[i]);
    if (j != null) return new int[]{j, i};
    indexByValue.put(nums[i], i);
}
```

**Биекция — это две мапы.** В [WeirdComparison](../src/ya/algorithm_course/fourth_sprint_hashes/WeirdComparison.java) (≈LC 205) одной мапы `a → b` мало: она не заметит, что два разных символа отобразились в один. Нужна вторая мапа `b → a`.

**Массив вместо мапы.** Если ключи — строчные латинские буквы, `int[26]` с индексом `c - 'a'` быстрее и проще мапы.

**Мапа + вторая структура.** В [RandomizedSet](../src/leetcode/medium/RandomizedSet.java) (LC 380) мапа «значение → индекс в списке» даёт поиск за O(1), а список — случайный элемент за O(1). Удаление: переносим последний элемент списка в освободившуюся ячейку и обновляем его индекс в мапе.

## 3. Префиксные суммы

**Соглашение:** `prefix[i]` — сумма первых `i` элементов, то есть `nums[0..i-1]`. Массив на один длиннее исходного, `prefix[0] = 0` — сумма пустого префикса.

Тогда сумма на отрезке `[l, r]` включительно равна `prefix[r + 1] - prefix[l]`.

Откуда `+1`: в префикс длины `r + 1` входит элемент `r`, а в префикс длины `l` элемент `l` не входит. Если определить `prefix[i]` как сумму по индекс `i` включительно, формула станет `prefix[r] - prefix[l - 1]` и сломается при `l = 0`. Поэтому удобнее первое соглашение.

### Подмассив с суммой ровно k

Сумма отрезка равна k, когда разность двух префиксных сумм равна k. Идём слева направо и для текущей суммы `sum` спрашиваем: сколько раз раньше встречалась сумма `sum - k`?

```java
Map<Integer, Integer> countBySum = new HashMap<>();
countBySum.put(0, 1);            // пустой префикс
int sum = 0, result = 0;
for (int x : nums) {
    sum += x;
    result += countBySum.getOrDefault(sum - k, 0);
    countBySum.merge(sum, 1, Integer::sum);
}
```

**Зачем `put(0, 1)`.** Это пустой префикс. Без него не посчитаются подмассивы, которые начинаются с индекса 0.

### Самый длинный подмассив с нужной суммой

Вместо количества храним **первый** индекс, на котором встретилась сумма: `firstIndex.put(0, -1)`, длина равна `i - firstIndex.get(sum - k)`. Существующую запись не перезаписываем: чем раньше индекс, тем длиннее отрезок.

Пример: [Contest](../src/ya/algorithm_course/fourth_sprint_hashes/Contest.java) (≈LC 525). Заменяем 0 на −1, и задача «поровну нулей и единиц» превращается в «самый длинный подмассив с суммой 0», то есть в поиск двух одинаковых префиксных сумм.

### Префикс и суффикс

[productExceptSelf](../src/leetcode/medium/MediumSolutions.java) (LC 238): ответ для позиции `i` — произведение всего, что слева, на произведение всего, что справа. Два прохода: слева направо копим префикс, справа налево суффикс.

### Хеши подстрок

Та же идея, что у префиксных сумм, только для полиномиального хеша: [PrefixHash](../src/ya/algorithm_course/fourth_sprint_hashes/PrefixHash.java) считает хеш любой подстроки за O(1) как `h[r] − h[l−1]·p^len` по модулю. [SequenceKTimes](../src/ya/algorithm_course/fourth_sprint_hashes/SequenceKTimes.java) — скользящий хеш (Рабин–Карп).

## 4. Типичные ошибки

- Забыт пустой префикс: `put(0, 1)` или `put(0, -1)`.
- В задаче на самый длинный отрезок перезаписан первый индекс суммы.
- В Java `Integer` сравнивается через `==`. Для значений вне диапазона −128…127 это сравнение ссылок и даёт `false`. Нужен `equals` или распаковка в `int`.
- Сумма не помещается в `int` — нужен `long`.
- Ключ мапы — изменяемый объект (массив, список). Массив как ключ вообще не работает: у него `hashCode` по ссылке.

## 5. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| Мапа для поиска пары | два указателя | массив уже отсортирован — мапа не нужна, O(1) памяти |
| Префиксные суммы + мапа | скользящее окно | все числа положительные и условие «≥» или «≤», а не «ровно» |
| `HashMap` | `TreeMap` | нужен порядок ключей: ближайший больший, минимум, диапазон |
| Подсчёт в мапе | алгоритм Бойера–Мура | просят O(1) памяти для элемента, встречающегося больше n/2 раз |
