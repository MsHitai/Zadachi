# Стек и монотонный стек

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

Главная мысль: стек нужен, когда **последнее открытое должно закрыться первым**, или когда элемент «ждёт» свой ответ, который появится позже.

---

## 1. Как узнать задачу

| Что написано в условии | Подход |
|---|---|
| Скобки, вложенность, теги, «корректна ли последовательность» | стек открывающих элементов |
| Вычислить выражение, обратная польская запись | стек чисел |
| Распаковать вложенную строку вида `3[a2[c]]` | два стека: множители и накопленные строки |
| «Ближайший больший / меньший элемент слева / справа» | монотонный стек |
| «Сколько дней ждать до более тёплого», «следующая более высокая цена» | монотонный стек |
| Наибольший прямоугольник в гистограмме | монотонный стек |
| Стек с минимумом или максимумом за O(1) | параллельный стек минимумов |
| Отмена действий, история, обход в глубину без рекурсии | обычный стек |

Сигнал для монотонного стека: наивное решение — для каждого элемента идти влево или вправо до первого большего или меньшего, то есть O(n²).

В Java для стека берут `Deque<Integer> stack = new ArrayDeque<>()` и методы `push`, `pop`, `peek`. Класс `Stack` устарел.

---

## 2. Обычный стек

**Смысл:** в стеке лежит то, что открыто и ещё не закрыто.

```java
Deque<Character> stack = new ArrayDeque<>();
for (char c : s.toCharArray()) {
    if (открывающая(c)) {
        stack.push(c);
    } else {
        if (stack.isEmpty() || !пара(stack.pop(), c)) return false;
    }
}
return stack.isEmpty();
```

Две проверки, которые забывают:

- **Перед `pop` стек может быть пуст** — закрывающая скобка без открывающей.
- **После цикла стек может быть не пуст** — остались незакрытые скобки.

Примеры из репозитория:

- [ValidParentheses](../src/leetcode/challenges/ValidParentheses.java) (LC 20).
- [PolskaCalculator](../src/ya/algorithm_course/second_sprint_recursion/PolskaCalculator.java) (≈LC 150): число кладём в стек, на операции снимаем два. Порядок важен: первым снимается **правый** операнд, для вычитания и деления это существенно.
- [PackedPrefix](../src/ya/algorithm_course/eighth_sprint_strings/final_task/PackedPrefix.java) (≈LC 394): на `[` запоминаем в стеках текущий множитель и накопленную строку, на `]` достаём их и склеиваем. Множитель может быть многозначным — цифры надо накапливать.
- [StackMax](../src/ya/algorithm_course/second_sprint_recursion/StackMax.java) (≈LC 155): второй стек хранит максимум для каждого уровня основного стека, поэтому после `pop` прежний максимум сразу известен.

## 3. Монотонный стек

**Смысл:** в стеке лежат **индексы** элементов, которые ещё не нашли свой ответ. Значения по этим индексам идут монотонно.

**Правило:** выталкиваем из стека тех, для кого текущий элемент является ответом.

Шаблон «следующий больший элемент справа»:

```java
int[] answer = new int[n];
Arrays.fill(answer, -1);
Deque<Integer> stack = new ArrayDeque<>();
for (int i = 0; i < n; i++) {
    while (!stack.isEmpty() && nums[stack.peek()] < nums[i]) {
        answer[stack.pop()] = i;   // для вытолкнутого ответ — текущий i
    }
    stack.push(i);
}
// кто остался в стеке — для тех большего справа нет
```

Сложность O(n): каждый индекс один раз кладётся в стек и не более одного раза снимается.

**Как не запутаться в знаке сравнения.** Не запоминаем «возрастающий или убывающий», а выводим из правила:

- Ищем следующий **больший** → выталкиваем, пока вершина **меньше** текущего.
- Ищем следующий **меньший** → выталкиваем, пока вершина **больше** текущего.

**Почему индексы, а не значения.** По индексу можно получить и значение, и расстояние (`i - stack.peek()`). По значению индекс не восстановить.

**Строгое или нестрогое сравнение.** Разница проявляется только на одинаковых элементах. `<` означает «равный элемент не считается большим», `<=` — «считается». Смотрим в условии, что нужно для равных.

### Наибольший прямоугольник в гистограмме

[LargestRectangle](../src/leetcode/hard/LargestRectangle.java) (LC 84). В стеке — индексы столбцов по возрастанию высоты. Когда приходит столбец ниже вершины, вершину снимаем: её прямоугольник дальше вправо расти не может.

Для снятого столбца `top`:

- правая граница — текущий `i` (первый более низкий справа);
- левая граница — новая вершина стека (первый более низкий слева);
- ширина равна `i - stack.peek() - 1`, а если стек пуст, то `i`.

Откуда `- 1`: обе границы не входят в прямоугольник, между индексами `a` и `b` не включая концы лежит `b - a - 1` элементов.

После конца массива стек нужно доразобрать, как будто пришёл столбец высоты 0. В решении это сделано условием `while (i < n || stackIndex > 0)`.

## 4. Типичные ошибки

- `pop` или `peek` на пустом стеке.
- Не проверен остаток в стеке после цикла.
- В стеке значения вместо индексов, а потом понадобилось расстояние.
- В польской записи перепутан порядок операндов.
- Для деления отрицательных чисел в Java `/` округляет к нулю, а условие может требовать округления вниз (`Math.floorDiv`).

## 5. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| Стек | очередь | обрабатывать надо в порядке поступления, а не в обратном |
| Монотонный стек | монотонная очередь (LC 239) | нужен максимум в **окне**, элементы устаревают слева |
| Монотонный стек | два указателя | Trapping Rain Water решается обоими; с указателями память O(1) |
| Монотонный стек | куча | нужен k-й по величине, а не ближайший по позиции |
