# Динамическое программирование

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

Главная мысль: ДП — это перебор всех вариантов, в котором одинаковые подзадачи считаются один раз. Половина успеха — сначала понять, **нужно ли здесь ДП вообще**: его легко применить там, где хватает окна или жадного прохода.

---

## 1. Как узнать задачу

Сигналы в условии:

- «Сколько способов…»
- «Минимальная стоимость / максимальная прибыль / наибольшая длина…»
- «Можно ли набрать, разбить, составить…»
- На каждом шаге есть **выбор** (взять или не взять, шагнуть на 1 или на 2), и выбор влияет на то, что доступно дальше.
- Речь о **подпоследовательности** (элементы можно пропускать) или о двух строках сразу.

Два обязательных свойства:

1. **Ответ собирается из ответов на меньшие задачи того же вида.**
2. **Подзадачи повторяются.** Если не повторяются — это просто рекурсия или «разделяй и властвуй».

### Когда это НЕ ДП

| Признак | Что вместо ДП |
|---|---|
| Ответ — **непрерывный** отрезок, состояние пересчитывается за O(1) | скользящее окно или один проход |
| Локально лучший выбор всегда верен, контрпример не строится | жадный алгоритм |
| Нужно **перечислить все** варианты, а не посчитать их | перебор с возвратом |
| Конкретный ответ легко проверить, условие монотонно | бинарный поиск по ответу |
| Подзадачи не пересекаются | обычная рекурсия |

В репозитории есть наглядные пары «ДП против простого решения»:

- [canJump](../src/leetcode/medium/MediumSolutions.java) (LC 55) через массив `dp` за O(n²) и [canJumpNoDp](../src/leetcode/medium/MediumSolutions.java) за O(n): достаточно одной переменной «самая дальняя достижимая позиция».
- [jumpDp](../src/leetcode/medium/MediumSolutions.java) и жадный [jump](../src/leetcode/medium/MediumSolutions.java) (LC 45).
- [maxProfit](../src/leetcode/easy/EasySolutions.java) и [maxProfitNoDp](../src/leetcode/easy/EasySolutions.java) (LC 121): хватает минимума слева.

Вопрос-фильтр перед тем, как заводить массив `dp`: **сколько информации о прошлом на самом деле нужно?** Если одно-два числа (максимум, минимум, сумма) — массив не нужен.

## 2. Пять вопросов

1. **Что хранит `dp[i]`?** Сформулировать словами, полным предложением. Это самый важный шаг.
2. **Как `dp[i]` выражается через предыдущие?** Перебрать варианты последнего шага.
3. **Какие значения известны сразу?** База.
4. **В каком порядке заполнять?** Так, чтобы всё нужное уже было посчитано.
5. **Где лежит ответ?** Не всегда в последней ячейке.

Если формула не выводится, обычно виноват первый вопрос: в состоянии не хватает информации. Тогда добавляют измерение — `dp[i][j]`.

**С чего начать, если непонятно.** Написать рекурсию «с конца»: какой был последний шаг и что осталось? Потом добавить запоминание результатов (memoization). Таблица снизу вверх — это та же рекурсия, развёрнутая в цикл.

## 3. Семейства задач

| Семейство | Что хранит состояние | Пример в репозитории |
|---|---|---|
| Линейное | `dp[i]` — ответ для первых `i` элементов | [ClimbingStairs](../src/leetcode/challenges/ClimbingStairs.java) (LC 70), [AllaLadders](../src/ya/algorithm_course/seventh_sprint_dynamic/AllaLadders.java) |
| «Заканчивается в i» | `dp[i]` — лучший ответ, который **заканчивается** на элементе `i` | [LargestDividerSubSelect](../src/stepik/algorithms/LargestDividerSubSelect.java) (≈LC 368), LIS |
| Рюкзак 0/1 | `dp[s]` — можно ли набрать сумму `s` | [SameSums](../src/ya/algorithm_course/seventh_sprint_dynamic/final_task/SameSums.java) (≈LC 416), [LeprechaunThieves](../src/ya/algorithm_course/seventh_sprint_dynamic/LeprechaunThieves.java) |
| Рюкзак с повторами | `dp[s]` — минимум монет для суммы `s` | [CoinChange](../src/stepik/algorithms/CoinChange.java) (LC 322) |
| Разбиение строки | `dp[i]` — можно ли разбить префикс длины `i` | [CheatSheet](../src/ya/algorithm_course/eighth_sprint_strings/final_task/CheatSheet.java) (≈LC 139) |
| Две строки | `dp[i][j]` — ответ для префиксов длины `i` и `j` | [LevenshteinDistance](../src/ya/algorithm_course/seventh_sprint_dynamic/final_task/LevenshteinDistance.java) (≈LC 72) |
| Сетка | `dp[r][c]` — лучший путь до клетки | [FlowerField](../src/ya/algorithm_course/seventh_sprint_dynamic/FlowerField.java) (≈LC 64) |

### Линейное

```java
int[] dp = new int[n + 1];
dp[0] = 1;                       // один способ стоять на месте
dp[1] = 1;
for (int i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
}
return dp[n];
```

### «Заканчивается в i»

Для наибольшей возрастающей подпоследовательности `dp[i]` — длина лучшей, которая заканчивается ровно на `nums[i]`. Ответ — **максимум по всему массиву `dp`**, а не `dp[n - 1]`: лучшая подпоследовательность не обязана заканчиваться последним элементом.

Вариант за O(n log n) с бинарным поиском по «хвостам» — [LongestSubSequence](../src/stepik/algorithms/LongestSubSequence.java) (≈LC 300).

### Рюкзак: направление цикла

```java
boolean[] dp = new boolean[target + 1];
dp[0] = true;
for (int x : nums) {
    for (int s = target; s >= x; s--) {    // с конца: каждый предмет один раз
        dp[s] = dp[s] || dp[s - x];
    }
}
```

- Суммы перебираем **по убыванию** → каждый предмет используется не больше одного раза. `dp[s - x]` ещё хранит значение без текущего предмета.
- Суммы перебираем **по возрастанию** → предмет можно брать многократно. `dp[s - x]` уже учитывает текущий предмет.

В Coin Change жадность (брать самую крупную монету) не работает. Контрпример: монеты 1, 3, 4, сумма 6. Жадно получится 4 + 1 + 1, три монеты; оптимально 3 + 3, две.

### Две строки

Таблица размера `(n + 1) × (m + 1)`. Индекс — **длина префикса**, а не позиция символа, поэтому символ для ячейки `[i][j]` — это `a.charAt(i - 1)` и `b.charAt(j - 1)`. Нулевая строка и нулевой столбец — база для пустой строки.

Откуда `- 1`: префикс длины `i` заканчивается символом с индексом `i - 1`. Соглашение «индекс — это длина» избавляет от особых случаев на границах.

## 4. Приёмы

- **Начальные значения.** Для минимума — «бесконечность», для количества способов — `dp[0] = 1`. В качестве бесконечности не брать `Integer.MAX_VALUE`: прибавление единицы переполнит его. Подходит `amount + 1` или `Integer.MAX_VALUE / 2`.
- **Экономия памяти.** Если строка таблицы зависит только от предыдущей, храним две строки или одну.
- **Восстановление ответа.** Запоминаем, откуда пришли (массив `prev`), или идём по готовой таблице с конца: [FlowerFieldWithPrevious](../src/ya/algorithm_course/seventh_sprint_dynamic/FlowerFieldWithPrevious.java), [CoinChange](../src/stepik/algorithms/CoinChange.java).
- **Скользящая сумма.** Если `dp[i]` — сумма последних k значений, её не пересчитывают заново, а обновляют: [AllaLadders](../src/ya/algorithm_course/seventh_sprint_dynamic/AllaLadders.java).

## 5. Типичные ошибки

- Состояние не сформулировано словами — формула подбирается наугад.
- Размер массива `n` вместо `n + 1`.
- Ответ взят из последней ячейки, хотя нужен максимум по всем.
- В рюкзаке 0/1 суммы перебираются по возрастанию.
- Переполнение при подсчёте количества способов — нужен `long` или взятие по модулю.
- В Coin Change II (LC 518) перепутан порядок циклов: монеты во внешнем цикле дают комбинации, суммы во внешнем — перестановки.

## 6. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| ДП: «максимальная сумма подмассива» | один проход (Кадане) | отрезок непрерывный, хватает одной переменной |
| ДП: «самая длинная подстрока с условием» | скользящее окно | подстрока, а не подпоследовательность |
| ДП: «максимум непересекающихся отрезков» | жадность | сортировка по концу, см. [Schedule](../src/ya/algorithm_course/seventh_sprint_dynamic/Schedule.java) |
| Жадность: «минимум монет» | ДП | локальный выбор портит остаток, есть контрпример |
| Перебор с возвратом: «сколько способов» | ДП | нужен только счётчик, а не список |
| ДП по сетке | BFS | ходить можно в любую сторону, порядок заполнения не определён |
