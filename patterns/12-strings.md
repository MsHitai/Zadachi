# Строки

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

Главная мысль: «строки» — это не один паттерн, а формат данных. Почти каждая строковая задача сводится к уже известному приёму. Задача при чтении условия — понять, **к какому именно**.

## 2. Строки в Java

- `String` неизменяема. Склейка в цикле через `+` создаёт каждый раз новую строку — это O(n²). Нужен `StringBuilder`.
- Сравнивать через `equals`, а не `==`.
- `s.substring(begin, end)`: `end` не включается, длина результата `end - begin`. Стоит O(длина).
- Индекс буквы: `c - 'a'`. Цифра из символа: `c - '0'`.
- `Character.isLetterOrDigit`, `Character.toLowerCase` — для задач вроде Valid Palindrome.
- Если строку нужно менять на месте — `char[] chars = s.toCharArray()`.

## 3. Расширение от центра

Для задач «самая длинная палиндромная подстрока» (LC 5) и «сколько палиндромных подстрок» (LC 647). У палиндрома есть центр; перебираем все центры и расширяемся, пока символы совпадают.

```java
int expand(String s, int left, int right) {
    while (left >= 0 && right < s.length() && s.charAt(left) == s.charAt(right)) {
        left--;
        right++;
    }
    return right - left - 1;      // длина палиндрома
}
```

Центров два вида: один символ (`expand(s, i, i)`, нечётная длина) и промежуток между символами (`expand(s, i, i + 1)`, чётная длина). Второй вид забывают чаще всего.

Откуда `right - left - 1`: после цикла оба указателя стоят на один шаг **за** границами палиндрома. Между индексами `left` и `right`, не включая их самих, лежит `right - left - 1` символов.

Условие цикла — по общему правилу: в теле читаются `charAt(left)` и `charAt(right)`, значит оба индекса сначала проверяются на границы.

## 4. Бор (Trie)

Дерево, где путь от корня — это префикс. Нужен, когда слов много и вопросы касаются префиксов.

```java
class TrieNode {
    TrieNode[] children = new TrieNode[26];
    boolean isWord;
}

void insert(TrieNode root, String word) {
    TrieNode node = root;
    for (char c : word.toCharArray()) {
        int i = c - 'a';
        if (node.children[i] == null) node.children[i] = new TrieNode();
        node = node.children[i];
    }
    node.isWord = true;
}
```

Флаг `isWord` обязателен: без него нельзя отличить слово от префикса другого слова («car» и «card»).

Пример: [CheatSheet](../src/ya/algorithm_course/eighth_sprint_strings/final_task/CheatSheet.java) (≈LC 139) — словарь лежит в боре, ДП по позициям текста идёт по бору от каждой достижимой позиции.

## 5. Поиск подстроки

- На собеседовании для простого случая достаточно сравнения в лоб за O(n·m) или `indexOf`.
- **Рабин–Карп:** сравниваем хеши подстрок, хеш окна пересчитывается за O(1). См. [SequenceKTimes](../src/ya/algorithm_course/fourth_sprint_hashes/SequenceKTimes.java) и [PrefixHash](../src/ya/algorithm_course/fourth_sprint_hashes/PrefixHash.java). Совпадение хешей не гарантирует совпадения строк — при необходимости сверяют посимвольно.
- **КМП:** O(n + m) через префикс-функцию. Писать наизусть просят редко; достаточно знать, что он существует, его сложность и идею: при несовпадении шаблон сдвигается не на один символ, а на длину уже совпавшей части, которая является одновременно префиксом и суффиксом.
- [SearchWithMove](../src/ya/algorithm_course/eighth_sprint_strings/SearchWithMove.java) (≈LC 28): шаблон ищется с точностью до сдвига всех значений, поэтому сравниваются не сами числа, а разности соседних.

## 6. Симуляция

Задачи вроде Zigzag, Roman, Text Justification паттерна не имеют: нужно аккуратно выполнить правила из условия. Трудность не в идее, а в граничных случаях.

Как подходить:

1. Выписать правила списком до кода.
2. Найти особые случаи: первая и последняя строка, одно слово, пустой ввод, одна строка в зигзаге.
3. Прогнать пример из условия руками.
4. Вынести повторяющиеся куски в маленькие методы.

Примеры из репозитория:

- [fullJustify](../src/leetcode/hard/HardSolutions.java), [BestTextJustify](../src/leetcode/hard/BestTextJustify.java) (LC 68). Слова в строку набираются жадно. Лишние пробелы делятся на промежутки: каждому `extra / gaps`, остаток `extra % gaps` — первым промежуткам по одному. Два особых случая: последняя строка и строка из одного слова выравниваются по левому краю.
- [convert](../src/leetcode/medium/MediumSolutions.java) (LC 6): по строке на каждый ряд, направление меняется на первом и последнем ряду. Особый случай — один ряд.
- [RomanToInteger](../src/leetcode/challenges/RomanToInteger.java) (LC 13): если символ меньше следующего — вычитаем, иначе прибавляем. [intToRoman](../src/leetcode/medium/MediumSolutions.java) (LC 12): жадно от больших значений, пары вроде `CM` и `IV` включены в таблицу.
- [reverseWords](../src/leetcode/medium/MediumSolutions.java) (LC 151): лишние пробелы по краям и между словами.

## 8. Типичные ошибки

- Склейка строк в цикле через `+`.
- `==` вместо `equals`.
- Ошибка на единицу в `substring`.
- Не обработаны пустая строка и строка из одного символа.
- Забыт регистр или небуквенные символы.
- В задаче на палиндромы забыты центры чётной длины.

## 9. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| Окно: «самая длинная …» | ДП | подпоследовательность, а не подстрока |
| Мапа со словами | бор | вопросы про префиксы, а не про слова целиком |
| ДП для палиндромов | расширение от центра | та же сложность O(n²), но память O(1) и код короче |
| Стек | счётчик | скобки одного вида: достаточно числа открытых |
