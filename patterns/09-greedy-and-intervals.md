# Жадные алгоритмы и интервалы

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

Главная мысль: жадный алгоритм на каждом шаге берёт локально лучший вариант и никогда не возвращается. Код обычно короткий. Сложность в другом — **убедиться, что жадность здесь законна**.

---

## 1. Как узнать задачу

| Что написано в условии | Подход |
|---|---|
| Отрезки, встречи, расписание: слить пересекающиеся | сортировка по началу |
| Максимум непересекающихся отрезков, минимум удалений | сортировка по **концу** |
| Покрыть все отрезки минимальным числом точек | сортировка по концу |
| Минимум переговорных комнат, максимум одновременных событий | сортировка по началу + куча концов |
| «Можно ли добраться», «минимум прыжков» | держим самую дальнюю достижимую позицию |
| Условие связывает элемент с обоими соседями | два прохода: слева направо и справа налево |
| Раздать или сопоставить после сортировки | сортировка + два указателя |
| Дробить можно (взять часть предмета) | сортировка по удельной ценности |

## 2. Как проверить, что жадность работает

1. **Попробовать сломать.** Придумать маленький пример из трёх-четырёх элементов, где локально лучший выбор ведёт к худшему итогу. Нашёлся — нужна динамика.
2. **Аргумент обмена.** Взять любое оптимальное решение и показать, что его первый шаг можно заменить на жадный, не ухудшив ответ.

Признак, что жадность не сработает: выбор сейчас меняет набор доступных вариантов потом, и это зависит от конкретных чисел. Примеры: размен монет произвольных номиналов, рюкзак с неделимыми предметами.

Пара из репозитория: [GoldenRage](../src/ya/algorithm_course/seventh_sprint_dynamic/GoldenRage.java) — рюкзак, где предмет можно делить, решается жадно по удельной цене. [LeprechaunThieves](../src/ya/algorithm_course/seventh_sprint_dynamic/LeprechaunThieves.java) — предметы неделимы, и это уже ДП.

## 3. Интервалы

Почти всегда первым шагом идёт сортировка. Вопрос только — по началу или по концу.

**Когда два отрезка пересекаются.** После сортировки по началу достаточно сравнить начало текущего с концом предыдущего: `cur.start <= last.end`. Строгое сравнение или нестрогое — зависит от того, считаются ли пересекающимися отрезки, которые только касаются (`[1, 2]` и `[2, 3]`). Это надо прочитать в условии или спросить.

### Слияние — сортировка по началу

```java
Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));
List<int[]> merged = new ArrayList<>();
for (int[] cur : intervals) {
    if (merged.isEmpty() || merged.get(merged.size() - 1)[1] < cur[0]) {
        merged.add(cur);                              // не пересекается — новый отрезок
    } else {
        int[] last = merged.get(merged.size() - 1);
        last[1] = Math.max(last[1], cur[1]);          // пересекается — расширяем
    }
}
```

`Math.max` обязателен: текущий отрезок может целиком лежать внутри предыдущего, и тогда конец менять нельзя.

Пример: [IntervalsGarden](../src/ya/algorithm_course/third_sprint_sort/IntervalsGarden.java) (≈LC 56).

### Максимум непересекающихся — сортировка по концу

```java
Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));
int count = 0;
int lastEnd = Integer.MIN_VALUE;
for (int[] cur : intervals) {
    if (cur[0] >= lastEnd) {
        count++;
        lastEnd = cur[1];
    }
}
```

**Почему по концу.** Отрезок, который заканчивается раньше всех, оставляет больше всего места остальным. Сортировка по началу ломается на одном длинном отрезке, который начинается первым и перекрывает всё.

Примеры: [Schedule](../src/ya/algorithm_course/seventh_sprint_dynamic/Schedule.java) (≈LC 435), [CoverDotsByLines](../src/stepik/algorithms/CoverDotsByLines.java) (≈LC 452) — точку ставим в конец первого непокрытого отрезка, она покрывает и все отрезки, начавшиеся до неё.

### Минимум комнат

Сортируем по началу. В min-куче лежат времена окончания занятых комнат. Для очередной встречи: если самая ранняя комната освободилась (`heap.peek() <= start`) — вынимаем её. Затем кладём конец текущей встречи. Ответ — максимальный размер кучи.

## 4. Другие жадные приёмы

**Самая дальняя достижимая позиция.** [canJumpNoDp](../src/leetcode/medium/MediumSolutions.java) (LC 55): идём слева направо и обновляем `reachable = max(reachable, i + nums[i])`; если `i > reachable` — дальше не пройти. В [jump](../src/leetcode/medium/MediumSolutions.java) (LC 45) добавляется граница текущего прыжка: дошли до неё — делаем следующий прыжок до самой дальней из найденных позиций.

**Сброс при отрицательном балансе.** [canCompleteCircuit](../src/leetcode/medium/MediumSolutions.java) (LC 134): если на пути от станции A бак ушёл в минус на станции B, то ни одна станция между A и B стартом быть не может — начинаем со следующей после B. Если суммарно топлива не меньше, чем расхода, ответ существует.

**Два прохода.** [candy](../src/leetcode/hard/HardSolutions.java) (LC 135): условие «больше, чем у соседа с меньшим рейтингом» касается обоих соседей. Первый проход слева направо учитывает левого соседа, второй справа налево — правого, берём максимум. Тот же приём: [ClosestZero](../src/ya/algorithm_course/first_sprint_pointers/final_test/ClosestZero.java), Product Except Self, Trapping Rain Water.

**Сортировка и сопоставление.** [Cookies](../src/ya/algorithm_course/third_sprint_sort/Cookies.java) (≈LC 455): самому нетребовательному ребёнку отдаём самую маленькую подходящую печеньку.

## 5. Типичные ошибки

- Жадность применена без проверки на контрпример.
- Для задачи на максимум непересекающихся отрезков сортировка по началу.
- При слиянии забыт `Math.max`.
- Перепутано строгое и нестрогое сравнение для касающихся отрезков.
- Компаратор `(a, b) -> a[0] - b[0]` переполняется на больших по модулю числах. В LC 452 есть такой тест. Надёжно — `Integer.compare`.
- После цикла не добавлен последний накопленный отрезок (если результат копится в переменных, а не в списке).

## 6. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| Жадность: «минимум монет» | ДП | номиналы произвольные, контрпример 1, 3, 4 и сумма 6 |
| Жадность: «рюкзак» | ДП | предметы нельзя делить |
| ДП: Jump Game, Gas Station | жадность | хватает одной переменной состояния |
| Жадность по отрезкам | ДП | у отрезков есть веса, нужен максимум суммарного веса |
| Куча для комнат | сортировка всех событий | можно отсортировать начала и концы отдельно и пройти двумя указателями |
