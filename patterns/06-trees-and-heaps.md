# Деревья и кучи

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

Главная мысль про деревья: почти любая задача решается рекурсией, где надо **поверить, что функция уже работает для детей**, и ответить только на вопрос «как из ответов детей собрать ответ для узла».

Главная мысль про кучу: она нужна, когда раз за разом требуется текущий минимум или максимум, а набор элементов меняется.

---

## 1. Как узнать задачу

| Что написано в условии | Подход |
|---|---|
| Высота, диаметр, сбалансированность, сумма путей | рекурсия снизу вверх (ответ возвращается из детей) |
| Проверить свойство, зависящее от предков (границы, путь от корня) | рекурсия сверху вниз (данные передаются параметром) |
| «По уровням», «вид справа», минимальная глубина | BFS с очередью |
| Дерево поиска (BST) + «k-й по величине», «отсортированный порядок» | in-order обход |
| BST + поиск, вставка, удаление | спуск по одной ветке, O(высота) |
| «k наибольших / наименьших», «top k», «k-й по величине» | куча размера k |
| «Медиана потока» | две кучи |
| Слить k отсортированных последовательностей | куча из k текущих элементов |
| Всё время нужен самый ранний / самый дешёвый / самый близкий | куча (`PriorityQueue`) |

## 2. Рекурсия по дереву: пять вопросов

1. **Что функция возвращает для поддерева?** Сформулировать словами: «высоту», «true, если поддерево — BST», «максимальную сумму пути, идущего вниз из узла».
2. **Что она возвращает для `null`?** Это база рекурсии.
3. **Как собрать ответ узла из ответов левого и правого ребёнка?**
4. **Нужно ли что-то знать от предков?** Если да — это параметры функции.
5. **Совпадает ли возвращаемое значение с ответом задачи?** Часто нет: функция возвращает одно, а ответ обновляется в отдельной переменной.

```java
int height(TreeNode node) {
    if (node == null) return 0;
    int left = height(node.left);
    int right = height(node.right);
    return 1 + Math.max(left, right);
}
```

**Снизу вверх.** [IsBalancedTree](../src/ya/algorithm_course/fifth_sprint_trees/IsBalancedTree.java) (≈LC 110): функция возвращает высоту поддерева или −1, если оно не сбалансировано. Один проход вместо пересчёта высоты для каждого узла.

**Сверху вниз.** [SearchTree](../src/ya/algorithm_course/fifth_sprint_trees/SearchTree.java) (≈LC 98): вниз передаются границы `(min, max)`, в которых обязано лежать значение узла. Классическая ошибка — сравнивать узел только с его прямыми детьми: свойство BST касается всего поддерева, а не соседей.

**Пятый вопрос на примере.** В диаметре дерева (LC 543) функция возвращает высоту, а ответ — максимум по всем узлам от `left + right`. Путь через узел использует обе ветки, но вверх можно передать только одну.

## 3. Обход по уровням

```java
Queue<TreeNode> queue = new ArrayDeque<>();
if (root != null) queue.add(root);
while (!queue.isEmpty()) {
    int size = queue.size();          // сколько узлов на текущем уровне
    for (int i = 0; i < size; i++) {
        TreeNode node = queue.poll();
        // обработать node
        if (node.left != null) queue.add(node.left);
        if (node.right != null) queue.add(node.right);
    }
}
```

`size` запоминаем до внутреннего цикла: во время обработки уровня в очередь уже добавляются узлы следующего.

DFS или BFS: если в условии есть слово «уровень» или нужна ближайшая к корню вершина — BFS. Иначе рекурсивный DFS короче.

## 4. Дерево поиска

- In-order обход (левое поддерево, узел, правое) выдаёт значения BST по возрастанию. Поэтому «k-й наименьший» — это k-й узел in-order обхода.
- Поиск и вставка идут по одной ветке: [InsertNodeInTree](../src/ya/algorithm_course/fifth_sprint_trees/InsertNodeInTree.java) (≈LC 701).
- [PrintTreeRange](../src/ya/algorithm_course/fifth_sprint_trees/PrintTreeRange.java) (≈LC 938): in-order обход, печатаем значения из диапазона `[L, R]`. Решение обходит всё дерево. Улучшение, о котором спросят: в левое поддерево идти, только если значение узла больше `L`, в правое — только если меньше `R`.
- Удаление — [RemoveNode](../src/ya/algorithm_course/fifth_sprint_trees/final_task/RemoveNode.java) (≈LC 450). Три случая: нет детей — убираем; один ребёнок — ставим его на место узла; два ребёнка — заменяем значение на минимум правого поддерева и удаляем тот минимум.
- [GenerateUniqueTrees](../src/ya/algorithm_course/fifth_sprint_trees/GenerateUniqueTrees.java) (≈LC 96): количество BST из n узлов — числа Каталана; перебираем корень, слева i − 1 узлов, справа n − i.

## 5. Куча

Куча — это полное бинарное дерево в массиве, где родитель не больше детей (min-куча).

- Если корень лежит в ячейке 0: дети узла `i` — `2i + 1` и `2i + 2`, родитель — `(i - 1) / 2`.
- Если корень лежит в ячейке 1: дети — `2i` и `2i + 1`, родитель — `i / 2`.
- Вставка: кладём в конец и просеиваем вверх. Удаление вершины: ставим последний на место корня и просеиваем вниз. Обе операции O(log n).

В репозитории есть оба соглашения об индексах: [SiftHeap](../src/ya/algorithm_course/fifth_sprint_trees/SiftHeap.java) считает от 1, [HeapSort](../src/ya/algorithm_course/fifth_sprint_trees/final_task/HeapSort.java) — от 0 (там max-куча и извлечение максимума). Формулы не надо помнить обе: достаточно нарисовать кучу из трёх элементов и проверить на ней.

В Java `PriorityQueue` — это min-куча. Max-куча: `new PriorityQueue<>(Comparator.reverseOrder())`.

### Top-K

**Для k наибольших нужна min-куча размера k.** Это контринтуитивно, но выводится так: мы храним k лучших кандидатов, и выбрасывать надо худшего из них, то есть наименьшего. Он и должен лежать на вершине.

```java
PriorityQueue<Integer> heap = new PriorityQueue<>();   // min-куча
for (int x : nums) {
    heap.add(x);
    if (heap.size() > k) heap.poll();                  // выбросить наименьший
}
return heap.peek();                                    // k-й по величине
```

Сложность O(n log k) вместо O(n log n) у полной сортировки.

### Две кучи для медианы

Max-куча хранит меньшую половину чисел, min-куча — большую. Размеры отличаются не больше чем на 1, медиана — на вершинах.

## 6. Типичные ошибки

- Нет проверки на `null` в начале рекурсии.
- В Validate BST сравнение только с прямыми детьми. Для границ использовать `long` или `null`: значение узла может быть равно `Integer.MIN_VALUE`.
- Высота пересчитывается заново для каждого узла — O(n²) вместо O(n).
- Компаратор вида `(a, b) -> a - b` переполняется на больших числах. Надёжнее `Integer.compare(a, b)`.
- Для top-k наибольших взята max-куча и в неё сложены все элементы — работает, но это O(n log n) и O(n) памяти.
- Глубокая рекурсия на вырожденном дереве (цепочка) может переполнить стек.

## 7. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| Куча | сортировка | нужны все элементы по порядку и данные не меняются |
| Куча | quickselect | нужен один k-й элемент, данные статичны: O(n) в среднем |
| Куча | монотонный стек или очередь | нужен ближайший по позиции, а не лучший по значению |
| Рекурсия по дереву | ДП | это одно и то же: ДП на дереве и есть рекурсия снизу вверх |
| DFS по дереву | BFS | в условии уровни или кратчайшее расстояние от корня |
