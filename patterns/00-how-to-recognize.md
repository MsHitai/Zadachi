# Как понять, чем решать задачу

Указатель по всем заметкам этой папки. Здесь только распознавание: по каким словам условия выбирать подход. Подробности — в заметке каждого паттерна.

---

## 1. Первые пять минут с задачей

1. **Пересказать условие своими словами** и разобрать пример руками. Если определение запутанное — переформулировать.
2. **Посмотреть на ограничения.** Они говорят, какая сложность пройдёт (раздел 2).
3. **Ответить на три вопроса про данные:**
   - Вход отсортирован, или его можно отсортировать, не испортив ответ?
   - Ответ — непрерывный кусок, произвольный набор элементов или одно число?
   - Нужно найти один ответ, посчитать количество или перечислить все варианты?
4. **Найти сигнальные слова** (раздел 3).
5. **Назвать решение в лоб и его сложность.** Потом спросить: какую работу оно делает повторно? Ответ обычно указывает на паттерн.
6. **До кода записать одной фразой, что означают переменные** — указатели, состояние `dp`, содержимое стека. Условия циклов выводятся из этой фразы.

---

## 2. Что говорят ограничения

| Размер входа n | Проходит сложность | Типичные подходы |
|---|---|---|
| до 10–12 | O(n!) | перестановки, перебор с возвратом |
| до 20–25 | O(2ⁿ) | подмножества, битовые маски |
| до 500 | O(n³) | ДП по отрезкам, три вложенных цикла |
| до 5 000 | O(n²) | ДП с двумя индексами, перебор пар |
| до 10⁵–10⁶ | O(n log n) или O(n) | сортировка, куча, бинпоиск, два указателя, окно, хеш-мапа |
| 10⁹ и больше | O(log n) или O(1) | бинарный поиск по ответу, формула |

Другие подсказки из ограничений:

- Значения до 10⁹, и их складывают или перемножают → `long`.
- Значения только положительные → возможно окно. Есть отрицательные → окно по сумме не сработает.
- Алфавит из 26 букв → массив `int[26]` вместо мапы.
- «O(1) дополнительной памяти» → два указателя, перестановки на месте, XOR.

## 4. Главные развилки

Пары подходов, которые путают чаще всего. Каждая решается одним вопросом.

| Развилка | Вопрос | Ответ |
|---|---|---|
| Окно или ДП | Кусок непрерывный? | да — окно; элементы можно пропускать — ДП |
| Окно или префиксные суммы | Все числа неотрицательные и условие «не больше / не меньше»? | да — окно; иначе префиксные суммы и мапа |
| Два указателя или мапа | Массив отсортирован и индексы не нужны? | да — указатели; иначе мапа |
| ДП или жадность | Строится ли контрпример к локально лучшему выбору? | строится — ДП; нет — жадность |
| ДП или перебор с возвратом | Нужен список вариантов или число? | список — перебор; число — ДП |
| BFS или DFS | Нужен кратчайший путь или уровни? | да — BFS; иначе DFS |
| BFS или Дейкстра | У рёбер разные веса? | да — Дейкстра; нет — BFS |
| Куча или сортировка | Данные меняются, или нужно только k элементов? | да — куча; нет — сортировка |
| Бинпоиск по ответу или ДП | Легко ли проверить конкретный ответ и монотонно ли условие? | да — бинпоиск по ответу |
| Стек или куча | Нужен ближайший по позиции или лучший по значению? | по позиции — монотонный стек; по значению — куча |

## 5. Если паттерн не узнаётся

- Решить маленький пример руками и проследить, что именно вы делаете глазами: скорее всего, это и есть алгоритм.
- Назвать решение в лоб вслух. На собеседовании это нормальное начало, и от него легче оттолкнуться.
- Спросить себя, что изменится, если вход отсортировать.
- Спросить, какая структура данных дала бы нужную операцию за O(1) или O(log n).
- Подсказки брать по ступеням: сначала только название паттерна, потом смысл переменных, и лишь потом код.

После каждой задачи, решённой с подсказкой, записывать одну строку: **какой сигнал в условии я пропустила**. Из таких строк эта таблица и пополняется.
