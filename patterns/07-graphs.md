# Графы

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

Главная мысль: в условии слово «граф» обычно не звучит. Самое трудное — **увидеть граф**: понять, что считать вершинами и что рёбрами. После этого выбор алгоритма почти механический.

---

## 1. Как узнать задачу

Граф прячется за такими формулировками:

- сетка из клеток, острова, лабиринт — вершины это клетки, рёбра ведут к соседним;
- «зависит от», «нужно сделать до», порядок курсов или сборки — ориентированный граф зависимостей;
- «связаны ли», «сколько групп», друзья, провинции — компоненты связности;
- «превратить одно слово в другое за минимум шагов» — вершины это состояния, рёбра это допустимые ходы;
- города и дороги, стоимость проезда, задержка сигнала — взвешенный граф.

| Что нужно найти | Алгоритм |
|---|---|
| Достижимость, количество компонент, площадь острова | DFS или BFS |
| Кратчайший путь, рёбра **без весов** | BFS |
| Кратчайший путь, веса **неотрицательные** | Дейкстра |
| Порядок с учётом зависимостей, проверка на цикл в ориентированном графе | топологическая сортировка |
| Объединять группы и спрашивать «в одной ли группе» | Union-Find |
| Соединить все вершины минимальной ценой | минимальное остовное дерево (Прим, Краскал) |
| Расстояние сразу от нескольких источников | BFS с несколькими стартами |

---

## 2. Пять вопросов перед кодом

1. **Что такое вершина?** Клетка, курс, слово, пара «позиция + состояние».
2. **Что такое ребро?** Ориентированное или нет, с весом или без.
3. **Как хранить граф?** Список смежности `List<List<Integer>>`. Для сетки хранить ничего не нужно: соседи вычисляются.
4. **Что именно ищем?** По таблице выше выбирается алгоритм.
5. **Где отмечаем вершину посещённой?**

## 3. BFS

```java
int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
Queue<int[]> queue = new ArrayDeque<>();
queue.add(new int[]{startRow, startCol});
visited[startRow][startCol] = true;         // отмечаем при добавлении
int steps = 0;
while (!queue.isEmpty()) {
    int size = queue.size();
    for (int k = 0; k < size; k++) {
        int[] cell = queue.poll();
        if (этоЦель(cell)) return steps;
        for (int[] d : dirs) {
            int r = cell[0] + d[0], c = cell[1] + d[1];
            if (r < 0 || r >= rows || c < 0 || c >= cols) continue;
            if (visited[r][c] || стена(r, c)) continue;
            visited[r][c] = true;
            queue.add(new int[]{r, c});
        }
    }
    steps++;
}
return -1;
```

**Отмечать посещение при добавлении в очередь, а не при извлечении.** Иначе одна вершина попадёт в очередь много раз — от каждого соседа.

**Почему BFS даёт кратчайший путь.** Он обходит вершины слоями: сначала все на расстоянии 1, потом на расстоянии 2. Первый раз, когда вершина достигнута, — это кратчайший путь до неё. Верно только когда все рёбра одного веса.

**Несколько стартов** (LC 994 Rotting Oranges): кладём в очередь все источники сразу до начала цикла.

Примеры из репозитория: [MazeEscape](../src/ya/algorithm_course/sixth_sprint_graphs/MazeEscape.java) (≈LC 1091), [MaxIslandsDistance](../src/ya/algorithm_course/sixth_sprint_graphs/final_task/MaxIslandsDistance.java) (≈LC 695, 200).

## 4. DFS

```java
void dfs(int v) {
    visited[v] = true;
    for (int next : graph.get(v)) {
        if (!visited[next]) dfs(next);
    }
}
```

**Подсчёт компонент:** внешний цикл по всем вершинам; каждый запуск DFS из непосещённой вершины — новая компонента. Внешний цикл забывают чаще всего: граф не обязан быть связным.

На большой сетке рекурсия может переполнить стек. Тогда DFS пишут со своим стеком — [ConnectionSeeker](../src/ya/algorithm_course/sixth_sprint_graphs/ConnectionSeeker.java) (≈LC 323).

Время входа и выхода — [DFSInOutTime](../src/ya/algorithm_course/sixth_sprint_graphs/DFSInOutTime.java): основа для поиска циклов и топологической сортировки.

## 5. Топологическая сортировка

Работает только для ориентированного графа без циклов. Два способа.

**Через DFS и три цвета** — [TopologicalSort](../src/ya/algorithm_course/sixth_sprint_graphs/TopologicalSort.java) (≈LC 210). Белая вершина не посещена, серая — в обработке (мы сейчас внутри неё), чёрная — закончена. Вершину добавляем в ответ при выходе из неё, в конце ответ разворачиваем. **Пришли в серую вершину — нашли цикл.**

**Алгоритм Кана.** Считаем для каждой вершины число входящих рёбер. В очередь кладём вершины, у которых оно ноль. Достаём вершину, добавляем в ответ, уменьшаем счётчик у её соседей; кто дошёл до нуля — в очередь. Если в ответ попали не все вершины — в графе цикл.

## 6. Дейкстра

[BFSSitesDjiakstra](../src/ya/algorithm_course/sixth_sprint_graphs/BFSSitesDjiakstra.java) (≈LC 743).

```java
int[] dist = new int[n];
Arrays.fill(dist, Integer.MAX_VALUE);
dist[start] = 0;
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));
pq.add(new int[]{0, start});                 // {расстояние, вершина}
while (!pq.isEmpty()) {
    int[] top = pq.poll();
    int d = top[0], v = top[1];
    if (d > dist[v]) continue;               // устаревшая запись
    for (int[] edge : graph.get(v)) {        // {сосед, вес}
        int nd = d + edge[1];
        if (nd < dist[edge[0]]) {
            dist[edge[0]] = nd;
            pq.add(new int[]{nd, edge[0]});
        }
    }
}
```

**Ленивое удаление.** Из `PriorityQueue` нельзя дёшево убрать старую запись, поэтому при улучшении расстояния просто добавляем новую, а старую пропускаем проверкой `d > dist[v]`.

**С отрицательными весами Дейкстра не работает** — нужен Беллман–Форд.

Минимальное остовное дерево алгоритмом Прима устроено так же, только в куче лежит вес ребра, а не расстояние от старта: [MaxSpanningTree](../src/ya/algorithm_course/sixth_sprint_graphs/final_task/MaxSpanningTree.java) (≈LC 1584; там дерево максимальное).

## 7. Union-Find

В репозитории пока нет. Нужен, когда рёбра добавляются по одному и после каждого спрашивают про связность.

```java
int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);   // сжатие пути
    return parent[x];
}

boolean union(int a, int b) {
    int ra = find(a), rb = find(b);
    if (ra == rb) return false;     // уже в одной группе — ребро создало бы цикл
    parent[ra] = rb;
    return true;
}
```

Вначале `parent[i] = i`: каждая вершина сама себе группа.

## 8. Типичные ошибки

- Вершина отмечается посещённой при извлечении из очереди.
- Нет внешнего цикла по всем вершинам.
- Нет проверки границ сетки перед обращением к клетке.
- Неориентированное ребро добавлено только в одну сторону.
- BFS применён к взвешенному графу.
- В Дейкстре нет пропуска устаревших записей.
- В сетке перепутаны строки и столбцы: `grid[row][col]`, где `row` — это y.

## 9. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| DFS для кратчайшего пути | BFS | DFS находит какой-то путь, не кратчайший |
| BFS по сетке | ДП по сетке | ходить можно только вправо и вниз — это ДП, порядок обхода известен заранее |
| DFS для компонент | Union-Find | рёбра приходят по одному, вопросы идут вперемешку с добавлениями |
| Дейкстра | BFS | все веса равны — очередь с приоритетом не нужна |
| Backtracking по сетке | DFS | в Word Search (LC 79) отметку посещения надо снимать при возврате, в обычном DFS — нет |
