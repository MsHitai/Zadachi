# Перебор с возвратом (backtracking)

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

Главная мысль: это обход дерева решений в глубину. На каждом шаге делаем выбор, идём дальше, а вернувшись — **отменяем выбор** и пробуем следующий. Шаблон один, задачи отличаются тремя параметрами.

---

## 1. Как узнать задачу

- «Вернуть **все**…»: все подмножества, перестановки, комбинации, разбиения, расстановки.
- «Сгенерировать все корректные…»
- Маленькие ограничения: n до 15–20 для подмножеств, до 8–10 для перестановок.
- Головоломки на доске: ферзи, судоку, поиск слова в сетке.

Отличие от ДП: если нужно **перечислить** варианты — это перебор. Если нужно только **посчитать** их или найти лучший — скорее всего ДП.

Размер ответа подсказывает сложность: подмножеств 2ⁿ, перестановок n!. Быстрее перебрать их нельзя, поэтому ограничения в таких задачах маленькие.

## 2. Шаблон

```java
List<List<Integer>> result = new ArrayList<>();

void backtrack(int start, List<Integer> path) {
    if (решениеГотово(path)) {
        result.add(new ArrayList<>(path));     // копия!
        return;
    }
    for (int i = start; i < nums.length; i++) {
        if (!можноВзять(i)) continue;          // отсечение
        path.add(nums[i]);                     // выбрать
        backtrack(i + 1, path);                // углубиться
        path.remove(path.size() - 1);          // отменить выбор
    }
}
```

Пять вопросов перед кодом:

1. **Что такое частичное решение?** Что лежит в `path`.
2. **Какие варианты есть на текущем шаге?** По чему идёт цикл.
3. **Когда решение готово?** Условие выхода.
4. **Что можно отсечь заранее?** Ветки, которые точно не дадут решения.
5. **Как не получить дубликаты?**

## 3. Три параметра, которыми отличаются задачи

Путаница с `i`, `i + 1` и `0` в рекурсивном вызове выводится из двух вопросов: **можно ли брать элемент повторно** и **важен ли порядок**.

| Задача | Цикл начинается с | Рекурсивный вызов | Почему |
|---|---|---|---|
| Подмножества, комбинации (LC 78, 77) | `start` | `i + 1` | порядок не важен, каждый элемент один раз: идём только вперёд |
| Комбинации с повторным использованием (LC 39) | `start` | `i` | элемент можно взять снова, но назад не возвращаемся |
| Перестановки (LC 46) | `0` | массив `used[]` | порядок важен: на каждой позиции может стоять любой ещё не взятый |

**Зачем `start`.** Он запрещает возвращаться к элементам левее. Без него `[1, 2]` и `[2, 1]` попадут в ответ как разные комбинации.

**Когда записывать решение:**

- Подмножества — на каждом узле дерева, без условия: любое частичное решение уже является подмножеством.
- Комбинации и перестановки — только когда набрана нужная длина или сумма.

**Дубликаты во входных данных** (LC 90, 40). Сначала сортируем, потом на одном уровне пропускаем одинаковые значения:

```java
if (i > start && nums[i] == nums[i - 1]) continue;
```

Условие `i > start`, а не `i > 0`: первый элемент уровня брать можно всегда, пропускаем только повтор на том же уровне.

## 4. Примеры из репозитория

- [GenerateParenthesis](../src/ya/algorithm_course/third_sprint_sort/GenerateParenthesis.java) (≈LC 22). Вариантов на шаге два, и у каждого своё условие: открывающую скобку можно ставить, пока `open < n`; закрывающую — пока `close < open`. Второе условие и есть отсечение: оно не даёт построить некорректную последовательность.
- [letterCombinations](../src/leetcode/easy/EasySolutions.java) (LC 17). Шаг — это позиция в строке цифр, варианты — буквы текущей цифры. Решение готово, когда длина равна числу цифр. Пустой ввод — отдельный случай: ответ пустой список, а не список с пустой строкой.

## 5. Типичные ошибки

- **В результат добавлен сам `path`, а не его копия.** Все элементы ответа окажутся одним и тем же списком, в конце пустым.
- **Забыта отмена выбора** после рекурсивного вызова.
- Со `StringBuilder` отмена нужна (`deleteCharAt`), а со `String` — нет: конкатенация создаёт новую строку, и старая остаётся нетронутой.
- Перепутаны `i + 1` и `start + 1` в рекурсивном вызове. Нужен `i + 1`: продолжаем после выбранного элемента.
- В поиске по сетке (LC 79) клетка отмечена посещённой и отметка не снята при возврате.
- Проверка на дубликаты без предварительной сортировки.

---

## 6. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| Перебор: «сколько способов» | ДП | нужен счётчик, а не список |
| Перебор: «минимальное количество» | ДП или BFS | нужен один лучший вариант |
| Перебор по сетке | DFS | в обычном DFS посещение не отменяется: вершину достаточно обойти один раз |
| Перебор подмножеств | битовые маски | n ≤ 20: число от 0 до 2ⁿ − 1 кодирует подмножество, рекурсия не нужна |
