# Связные списки и проектирование структур данных

Примеры — из решений этого репозитория (каталог — [TASKS.md](../TASKS.md)).

Главная мысль про списки: алгоритмически они простые, вся сложность — в аккуратной работе со ссылками. Перед тем как перезаписать `next`, надо спросить себя: **не потеряю ли я остаток списка?**

Главная мысль про проектирование: ни одна структура не умеет всё за O(1), поэтому **комбинируют две**, каждая закрывает слабое место другой.

---

## 1. Как узнать задачу

| Что написано в условии | Приём |
|---|---|
| Голова списка может измениться (удаление, слияние, вставка в начало) | фиктивная голова (dummy) |
| Развернуть список или его часть | три указателя: `prev`, `curr`, `next` |
| Найти середину, проверить цикл | быстрый и медленный указатель |
| «k-й элемент с конца» за один проход | два указателя с разрывом в k |
| Слить отсортированные списки | dummy + указатель на хвост результата |
| «Реализуйте структуру с операциями за O(1)» | комбинация мапы со списком или массивом |
| Очередь или дек фиксированного размера | кольцевой буфер |

## 2. Приёмы для списков

### Фиктивная голова

Чтобы удалить или вставить узел, нужен **предыдущий** узел. У головы предыдущего нет, и появляется особый случай. Фиктивный узел перед головой убирает его.

```java
ListNode dummy = new ListNode(0);
ListNode tail = dummy;
while (a != null && b != null) {
    if (a.val <= b.val) { tail.next = a; a = a.next; }
    else                { tail.next = b; b = b.next; }
    tail = tail.next;
}
tail.next = (a != null) ? a : b;   // хвост прицепляем целиком
return dummy.next;
```

Пример: [Merge_Two_Sorted_Lists](../src/leetcode/challenges/Merge_Two_Sorted_Lists.java) (LC 21). Это то же слияние двумя указателями, что и для массивов, только хвост не нужно копировать поэлементно.

### Разворот

```java
ListNode prev = null, curr = head;
while (curr != null) {
    ListNode next = curr.next;   // сохранить остаток
    curr.next = prev;            // развернуть ссылку
    prev = curr;                 // сдвинуться
    curr = next;
}
return prev;
```

Порядок строк выводится из одного правила: сначала сохранить то, что сейчас будет перезаписано. В конце `curr == null`, новая голова — `prev`.

В [TestTheory](../src/ya/algorithm_course/first_sprint_pointers/TestTheory.java) (≈LC 206) список двусвязный: у каждого узла меняются местами `prev` и `next`.

### Быстрый и медленный указатель

```java
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
}
// slow — середина (при чётной длине вторая из двух средних)
```

Для цикла (LC 141): если внутри цикла `slow == fast`, цикл есть.

### Условие цикла `while` в списках

Правило то же, что для массивов: **условие защищает то, что разыменовывается в теле**.

- В теле только `curr.val` и `curr.next` → `while (curr != null)`. Обрабатываем каждый узел.
- В теле есть `curr.next.val` (сравниваем с соседом или удаляем следующий) → `while (curr != null && curr.next != null)`. Останавливаемся на предпоследнем.
- В теле есть `fast.next.next` → `while (fast != null && fast.next != null)`.

Примеры из репозитория: [RemoveDuplicates](../src/leetcode/challenges/RemoveDuplicates.java) (LC 83) — сравнение с соседом; [insertGCD](../src/leetcode/medium/MediumSolutions.java) (LC 2807) — вставка между текущим и следующим, после вставки шагаем через вставленный узел.

## 3. Проектирование структур

Вопрос для выбора: какая операция у какой структуры медленная и чем её закрыть?

| Задача | Комбинация | Что чем закрывается |
|---|---|---|
| Insert Delete GetRandom O(1) (LC 380) | `ArrayList` + `HashMap` значение → индекс | список даёт случайный доступ, мапа — поиск |
| LRU Cache (LC 146) | `HashMap` + двусвязный список | мапа даёт поиск, список — порядок использования и удаление из середины |
| Min Stack (LC 155) | два стека | второй помнит минимум на каждом уровне |
| Очередь на двух стеках (LC 232) | входной и выходной стек | переливаем, только когда выходной пуст |

[RandomizedSet](../src/leetcode/medium/RandomizedSet.java): удаление из середины списка стоит O(n), поэтому удаляемый элемент заменяем последним и удаляем уже последний. Порядок действий в решении: убрать ключ из мапы (и узнать индекс), снять последний элемент списка, и если удаляли не его — записать его в освободившуюся ячейку и обновить его индекс в мапе. Случай «удаляем сам последний элемент» проверяется условием `index < values.size()`.

### Кольцевой буфер

[CustomDeque](../src/ya/algorithm_course/second_sprint_recursion/CustomDeque.java) (≈LC 641), [RestrictedQueue](../src/ya/algorithm_course/second_sprint_recursion/RestrictedQueue.java) (≈LC 622).

- Шаг вперёд: `(i + 1) % n`.
- Шаг назад: `(i - 1 + n) % n`. Прибавляем `n`, потому что в Java остаток от отрицательного числа отрицательный.
- Пустую очередь от полной отличаем отдельным счётчиком `size`: по одним индексам головы и хвоста их не различить.

Своя хеш-таблица — [CustomHashTable](../src/ya/algorithm_course/fourth_sprint_hashes/final_task/CustomHashTable.java) (≈LC 706), метод цепочек. Это по сути массив связных списков, и удаление из середины цепочки — та же задача про предыдущий узел.

## 4. Типичные ошибки

- Перезаписали `next`, не сохранив остаток списка.
- `NullPointerException` на пустом списке или списке из одного узла.
- Вернули `head` вместо `dummy.next`, хотя голова изменилась.
- После разворота у бывшей головы остался старый `next` — получился цикл.
- В двусвязном списке обновили `next`, но забыли `prev`.
- В RandomizedSet не обновили индекс перенесённого элемента.

Проверять руками на трёх случаях: пустой список, один узел, два узла.

## 5. С чем не путать

| Выглядит как | Но на самом деле | Как отличить |
|---|---|---|
| Быстрый и медленный указатель | `HashSet` посещённых узлов | память O(n) допустима — сет проще; просят O(1) — указатели |
| Задача на список | задача на кучу | Merge k Sorted Lists (LC 23): список только формат данных, суть — куча из k голов |
| `LinkedHashMap` | своя мапа + список | на собеседовании по LRU обычно просят написать список самостоятельно |
